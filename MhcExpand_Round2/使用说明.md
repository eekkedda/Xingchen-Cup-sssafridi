# 资料包使用说明

本包用于第二轮研究、编码任务拆分与性能记录，**不是可直接提交 CANNJudge 的算子源码包**。

先让 coding agent 阅读 `给CodingAgent的执行指令.md`，再结合 `第二轮优化方案.md` 和实际仓库工作。`资料索引.json` 收录 22 项外部技术资料及 4 项上传材料的用途、版本和核查范围。

| 文件 | 用途 |
|---|---|
| 第二轮优化方案.md / .html | 完整分析、资源推导、候选机制、实验、正确性与来源 |
| 给CodingAgent的执行指令.md | 可直接传给仓库内 coding agent 的任务书 |
| 资料索引.json | 机器可读的官方资料/源码清单 |
| 历史跑分.json | 从交接表转录的历史数据，不是平台原始导出 |
| analyze_results.py | 离线比较时间，保留单位精度与显示量化范围 |
| test_analyze_results.py | 分析脚本单元测试，不是 Ascend kernel 测试 |
| 历史对比_*.md | 用脚本生成的两组历史对比 |
| 实验记录模板.json | 新实验记录骨架；未执行状态保持未执行 |

## 离线分析

仅需 Python 3.10 或更新版本和标准库，无需 CANN/NPU，无联网行为：

```bash
python -m unittest -v test_analyze_results.py
python analyze_results.py 历史跑分.json --baseline Baseline --candidate Round6
python analyze_results.py 历史跑分.json --baseline Round5 --candidate Round6
```

未来时间继续以带单位的字符串保存，例如 `"1.40 ms"`、`"3.90 us"`。不要先转成浮点再丢弃原始显示精度。`versions` 下每个版本支持多条完整 `runs`，每次应覆盖相同的测试点；平台真实分数保留在 `platform_score`，未知时为 null。

脚本输出不是官方分数，也不统计显著性。显示区间假定最后显示位四舍五入，不包括设备/运行噪声。单次 MAD 为零只是因为没有重复样本。

第二轮执行状态已不再停留于纯资料阶段：

- `round2_audit.md` 是对 Round 6 实际源码、tiling、UB、DMA 与同步的审计；
- `tiling_trace.json` 是用实际 Host 规则和本机 CANN 平台配置生成的公开形状 trace；
- E0、E1 和 E2 均已完成 CANN 8.5 `binary + install` 构建；
- E1 已形成当前待上平台候选和 7 文件提交包；
- E2 为独立 FP16 mixed Axpy 实验，未合并到当前 `B_easy`；
- msProf CA 模拟已执行 FP16/BF16 前后向对象，但配置模式未导出结果 tensor，不能当作完整 golden 正确性或真实 910B 性能验证。

具体状态、哈希与测量边界见 `round2_results.json` 和 `experiments/*.json`。离线分析脚本的 6 项测试及 reference 的 3 项测试已通过；reference 仍只验证公式，不执行 Ascend kernel。
