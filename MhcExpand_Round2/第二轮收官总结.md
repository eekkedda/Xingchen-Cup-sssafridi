## 3. 瓶颈定论(按测试点分层,全部有平台数据支撑)

### 3.1 小点 1、5(距 TBest 各 ~2.3μs,模型空间各 +8~9 分)——**延迟/启动型,已到 kernel 内部天花板**
三条独立证据链:
1. 标量指令 -3%(E4)~-34%(E5)平台无感(点1带 3.54~4.22、点5带 3.62~4.42 恒定);
2. 核数 32→12 无感(E4D1);
3. 官方 SetFlag/WaitFlag 文档证实"读→写等待往返"是编程模型强制
   (Set→Wait→依赖指令为唯一合法范式)。
剩余差距位于:kernel 启动、MTE2 读延迟、收尾排空、平台固定成本——
其中约 1.4μs 疑似为评测机 kernel 下发/测量固定开销(TBest 1.36 的存在证明
它对所有队伍 ≤1.4μs)。榜首 1.5~2.2 与我们 3.5~4.4 的差异,最可能是
某种我们未复现的常规结构(候选:极简 prologue 的更小 kernel 产物、
或其提交在低负载时段抽取的显示值),本地无真机无法进一步定位。

### 3.2 大点 3、6、7、8(距 TBest 1.4~3%)——**带宽型,贴形状上限**
- 前向命令数 ÷4(E4C1)与反向读命令 ÷2(E4G2)平台均无感;
- 模拟器 -21.5% wall 不迁移:CA 模拟器不建模跨核 HBM 带宽争用,
  真机上这些点已在形状允许的有效带宽 ceiling(2.6~3.0TB/s)附近。

### 3.3 中点 2、4(距 TBest 4~16%)——**噪声主导区**
- 同代码点 2 波动 15.44~17.64μs(±1μs ≈ ±1 分);
- E4G1 曾使点 4 创历史最好(46.74),但单次观测无法与噪声区分;
- 只有 >1.5 分的机制才可被确认——而这类机制已穷尽(见 3.1/3.2)。

### 3.4 评测与统计瓶颈
- 同代码分数 σ≈0.5(76.05 vs 74.86 同代码实测),<1.2 分的单次差异不可判;
- 评分模型 S=12.5·Σ1/(1+a·ln(Tᵢ/Bᵢ)),a≈2.444,13 次提交核验误差 ≤0.2 分;
- 评测环境会变更(E5 事件族被杀):任何新构造需先过"可移植构件"清单。

## 4. 方法论资产(第三大轮直接复用)

1. **平台诊断阶梯**:提交不限量 ⇒ 平台即 profiler;每实验单一变量+
   预注册读数规则+版本卡(基线/改动文件/哈希/粘贴自检特征串)
2. **CA 模拟器实操**(simulator/README_simulator.md):LD_LIBRARY_PATH
   两个目录、tiling bin 尺寸校验、"All task success"假阳性识别、
   多核 wall/每核 cycles 分析脚本(analyze_sim_run.py / analyze_per_core.py)
3. **mskpp 真实 host tiling 通道**(run_mskpp_case.py):tiling 生成已通,
   kernel 启动在本环境挂起未解——第三大轮若解决即得本地 golden 比对

## 6. 收割与终局协议

1. 以 E4G2(或任一回退包)重复提交抽噪声;**晚间/凌晨优先**
   (仅有的两次 ≥75.9 均在深夜时段)
2. 抽到 ≥75.9 冻结停手;单次 ≥76 概率约 4~7%,20~30 次提交有 50~70% 把握刷新
3. 回退保险(均 8/8 验证):E4G2 `aea1f45a...` / E4G1 `7948b569...` / E4 `2bd1ff4e...`
4. 截止前 48 小时:只交已验证字节;最终版本需两次平台通过;
   最后一次提交必须是当次最高分的原样重交(平台取最新提交显示)

## 7. 第三大轮候选方向(按预期排序)

1. **打通 mskpp 输出比对** → 解锁 DMA/同步结构类改动的本地安全网
2. 向赛方求证:评测计时口径(是否含 host/下发)、R6"纯搬运"边界、
   环境变更公告——若能拿到小点 1.4μs 固定成本的构成,3.1 的天花板或许可推
3. 小点若必须再攻:只剩"更小 kernel 产物/极简 prologue"一族
   (E4 已把 text 减半仍无感,预期很低)
4. 大点若必须再攻:HBM 访存模式(如 L2 命中率友好的任务排布)——
   需真机 profiling 支持,本地无法开发
