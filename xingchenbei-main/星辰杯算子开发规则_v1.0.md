# 中国电信星辰杯高校 AI 算子开发挑战赛

## 算子开发规则 v1.0

---

## 一、红线（禁止）

以下条款针对**最终提交版本**判定。开发过程中的中间态（如 host 先行实现、device 桩函数、临时 return）不构成违规，但最终提交须满足全部红线要求。

### R1. 禁止针对 case 编程

算子应具备泛化能力。判定标准是输入域覆盖，不是测试集分布：算子须对其声明支持的 shape/dtype 域内**任意合法输入**正确，而非仅对赛题测试用例正确。

### R2. 禁止将 NPU 计算转移到 host

本应由 NPU device kernel 执行的数值计算，不得在 host CPU 上执行后把结果传回 device。Host 仅可做本规则第三部分"允许条款"列明的工作，不得执行算子的数值计算（含参考实现）。

### R3. 禁止 hash(shape) / 指纹 / 白名单识别测试用例并走特殊快路径

按 shape / tiling key 做通用分派属于允许范围（见允许条款 A2）；禁止的是通过哈希、特征指纹、硬编码白名单等方式**识别具体测试用例**并跳转特殊路径。

### R4. 禁止结果重放

Kernel 内不得复用预存 golden 或历史输出，必须真实计算。同时禁止以下"假计算"手法：

- 只读不写
- 读无关 buffer 后 return
- 在 cache/L2/UB 中算对但不写回 `__gm__` 输出 buffer

### R5. 特化分支必须对域内所有合法输入正确

"域"的定义：该 tiling key 在算子 spec 下对应的合法输入集合。

任何按 shape/tiling key 的特化分支，须对该域内**全部**合法输入产出正确结果，不得仅对部分输入正确。

### R6. NPU kernel 不得为空操作或纯数据搬运

具体而言，NPU kernel 不得：

- 为空操作（无任何计算）
- 仅做 CopyData / Memcpy 数据搬运
- 在 kernel entry 内直接 return 跳过计算

### R7. 代码注释与残留

- **注释可作为违规证据之一**，但代码本身是主要判定依据；清理注释不构成免责。
- **Host 侧可保留参考实现用于自测**，但参考实现不得参与评分路径（不得被 NPU kernel 调用、不得作为输出回退）。参考实现的存在本身不构成违规。
- 提交版不得残留 hash / 白名单 / "针对某 case" 的注释或代码。

---

## 二、兜底条款

### R8. 开放式兜底（受约束）

任何行为等价于上述红线 R1–R7 的手法，均构成违规，即使未被逐条列举。判定标准是**是否绕过 NPU kernel 真实计算要求**。

约束：

- 兜底条款**仅适用于行为等价于已列举红线（R1–R7）的情形**。
- 裁定须在违规公示中写明"等价于第 X 条"的论证。
- **无法论证等价性的，不构成违规。** 

---

## 三、允许条款

### A1. Host 侧允许的工作

- Tiling 计算
- Workspace 分配
- 内存申请与拷贝（memcpy）
- Kernel launch 配置
- Shape / attr 校验

Host 不得执行算子的数值计算（含参考实现参与评分路径）。

### A2. 按 shape / tiling key 做通用分派

允许，但须同时满足以下三个条件：

1. **key 范围合理**：分派 key 须对应可解释的 shape/tiling 分类，不得是"测试用例编号"的变相编码。
2. **域内任意输入正确**：该 key 覆盖的输入域内，任意合法输入须产出正确结果。
3. **有可识别的 fallback 兜底**：fallback 须**产出数值正确的结果**，不得 fallback 到 host 计算、不得 return 错误码、不得是永远走不到的 `default: assert(0)`。

## 四、违规判定与公示

### D1. 判定透明化

赛方将在赛事期间持续公布违规判定的**脱敏摘要**，作为裁判标准的公开判例。每条公示包含：

| 字段 | 说明 |
|---|---|
| 题号 | 涉事题目编号 |
| 违反条款 | 如"红线 R2" |
| 手法描述 | 具体干了什么（隐去选手身份） |
| 判定依据 | 反编译结果 / fuzzing 输出 / asm 对比等 |
| 处理结果 | 警告 / 取消该题 / 取消全部等 |

公示只公开题号、条款、手法与依据。

### D2. 判定时间窗口

- 红线判定针对**最终提交版本**。
- 开发过程中的中间态不构成违规，但选手须确保最终提交满足红线要求。
- 赛方在赛后可对排名前列选手的 kernel 做**模糊测试（fuzzing）**，验证域内正确性（R5）。

## 五、后果（梯度处理）

### E1. 单题首次违规（情节较轻）

**适用情形**：违反 R6（空操作/纯搬运）、R7（host 参考实现参与评分路径）等，未涉及主观恶意。

**处理**：

- 该提交判无效
- 选手须重新提交合规版本，该题成绩按合规版本重新计算

- 书面警告并脱敏公示
- **不直接取消该题全部成绩**

### E2. 单题违规（情节严重）

**适用情形**：涉及 R1（针对 case）、R3（hash/白名单）、R4（结果重放）等主观作弊手法，或同一题重复违规。

**处理**：

- 取消该题成绩
- 选手须重新提交合规版本，该题成绩按合规版本重新计算
- 脱敏公示

### E3. 多题违规

**适用情形**：同一选手/队伍在 ≥2 道题上被判违规。

**处理区分情节**：

| 情节 | 处理 |
|---|---|
| 多题违规且情节属 R1/R3/R4（主观恶意） | 取消全部成绩，撤销排名，全量重排，选手可重新提交合规版本参赛。 |
| 多题违规但情节属 R6/R7 等（认知偏差、未读懂规则） | 取消相关题成绩，不取消全部，选手可重新提交合规版本参赛。 |

### E4. 成绩追溯性

违规提交、已删除提交、状态非 Pass 的提交，其所设成绩一律作废。选手须重新提交合规版本，该题成绩按合规版本重新计算。成绩具备追溯性，不因提交被删除或状态变更而保留违规高分。
